## 为什么embedding特征需要L2归一化？
```python
  norms = np.linalg.norm(embs, axis=1, keepdims=True)  # shape: (255755, 1)
  norms[norms == 0] = 1.0
  embs = embs / norms
```
对每个向量，除以它的 L2 范数（模长），使其长度变为 1：

原始向量: [0.3, 0.4]
L2 范数:  sqrt(0.3² + 0.4²) = 0.5
归一化后: [0.3/0.5, 0.4/0.5] = [0.6, 0.8]
验证:     sqrt(0.6² + 0.8²) = 1.0 ✓

为什么归一化？

归一化后，两个向量的点积 = 余弦相似度：

未归一化:  dot(A, B) = |A| × |B| × cos(θ)  ← 受向量长度影响
归一化后:  dot(A, B) = 1 × 1 × cos(θ) = cos(θ)  ← 纯粹衡量方向相似性

这样 Faiss 的 IndexFlatIP（内积索引）搜索结果就是余弦相似度排序。

norms[norms == 0] = 1.0 是什么？

某些文章的 embedding 可能全为 0（缺失），norm = 0，除以 0 会得到 NaN。把 0 替换为 1.0 后，0 / 1.0 = 0，向量保持为零向量，不会报错。
(这里也有特殊处理：1.默认全零 2.默认均值 3.默认类别均值)


## 面试官还会问的问题

### Q1: 为什么用 dtype 字典而不是让 pandas 自动推断？
pandas 默认读取整数为 int64、浮点为 float64，一个 int64 占 8 字节，int8 只占 1 字节。手动指定 dtype 可以节省 75%-87.5% 的内存，对于千万级点击日志效果显著。

### Q2: 为什么去重用三列而不是单列？
单列去重会误删不同时间的合法点击。三列 (user, item, timestamp) 完全相同才是真正的重复记录（数据采集bug），同一用户在不同时间点击同一篇文章是正常行为。

### Q3: reset_index(drop=True) 的作用？
drop 后 index 不连续（如 0,1,3,5...），reset_index 重置为 0,1,2,3...，避免后续 iloc/拼接时出错。drop=True 表示不把旧 index 保存为新列。

### Q4: 字典 vs DataFrame 查询的性能差异？
DataFrame 按条件查询是 O(n) 扫描，字典是 O(1) 哈希查找。推荐系统中每个用户需要频繁查历史、每个物品需要查属性，字典的 O(1) 查找在百万级数据下快 100-1000 倍。

### Q5: 为什么同时存归一化时间和绝对时间？
归一化时间 (0-1) 用于模型特征输入，数值范围小、训练稳定。绝对时间戳用于时间窗口过滤（如"最近27小时"），需要真实时间计算差值。两者用途不同，缺一不可。

### Q6: Leave-One-Out vs 随机划分 vs 时间划分？
- LOO: 每用户最后一条做测试，模拟"预测下一次点击"，最贴近真实场景
- 随机划分: 可能导致未来数据泄露到训练集
- 时间划分: 按全局时间切分，但用户活跃度不同时测试集分布不均

### Q7: embedding 全为 0 除了填 0 还有什么处理方式？
1. 默认全零向量（本项目方案）：简单但可能影响相似度计算
2. 默认均值向量：用所有 embedding 的均值填充，保留全局语义
3. 默认类别均值：用同 category 的 embedding 均值填充，更精准但需要额外计算

### Q8: Faiss 是什么？为什么用它？
Faiss 是 Facebook 开源的向量检索库，支持亿级向量的毫秒级最近邻搜索。IndexFlatIP 用内积检索，配合 L2 归一化等价于余弦相似度。比暴力搜索快 100-1000 倍。

### Q9: 多路召回融合时为什么要 per-user 归一化？
不同召回通道的分数尺度不同（ItemCF 是共现计数 0-100，YouTubeDNN 是余弦相似度 0-1），直接加权会导致大尺度通道主导结果。Per-user MinMax 归一化到 [0,1] 后才能公平融合。
